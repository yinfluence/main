# 关键词全量重写计划（2026-05-11）

## 目标

把当前网站最终显示的全部关键词页面按统一标准重写并审查一遍。这里的“关键词”以 `docs/data/site.json` 构建后的 `site.keywords` 为最终口径；内容可以来自 `content/keywords`、`content/people`、概念/模型/主题继承、节目标签和批量定义文件，但验收只看最终关键词页面是否达标。

## 本次任务结束标准

本次任务只有在以下条件全部满足时才算结束：

1. 进度台账中全部关键词状态都变成 `reviewed` 或 `accepted_with_known_limit`，没有 `pending`、`assigned`、`drafted`、`needs_rework`。
2. 每个关键词都按 `kind` 完成类型归类，并按该类型补齐对应内容结构：基础说明、节目关联、常见场景或类型专属字段、延展阅读。
3. 主整理者已经审过每个关键词。agent 只负责写初稿或返修，最终是否通过由主整理者在台账里记录。
4. `npm run build` 成功，`docs/` 已同步生成。
5. `npm run audit:keywords` 不再出现 stale site data、旧模板、明显薄内容、人物字段缺失、人物 `signalNotes`、目录污染等本轮要消除的问题。
6. 最终生成的 `docs/data/site.json` 和本地页面不再显示 `待补充`、`暂无`、`后续补充`，正文不再出现“截至某日核对 / 截至本次核对 / 页面整理时”这类时效口吻。
7. 本地页面抽查通过，至少覆盖人物、地缘/地点、公司/机构、产品/技术、事件、机制、概念、主题、金融资产/商品、常规词。
8. 更新 `src/app.js` 的网页日志 `WEBSITE_LOG_ENTRIES`，说明本次关键词体系重写、页面结构和数据质量改动。
9. 运行最终验证后，按 Lore Commit Protocol 提交，并 `git push yinfluence-origin main`。

只要没有完成第 1-9 条，本次关键词全量重写就没有结束。

## 进度台账

台账文件：`.omx/state/keyword-rewrite/progress.json`

每个关键词记录：

- `id`
- `name`
- `kind`
- `sourceType`
- `sourceFile`
- `referenceCount`
- `status`
- `assignedAgent`
- `lastBatch`
- `reviewNotes`
- `riskNotes`

状态含义：

- `pending`：还没派发或还没按新标准整理。
- `assigned`：已派给 agent，等待返回。
- `drafted`：agent 已写入，主整理者未审。
- `needs_rework`：主审要求返修。
- `reviewed`：主审通过。
- `accepted_with_known_limit`：可用但有已记录的低风险限制。

## 分配规则

每轮最多 6 个 agent。每个 agent 至少 10 个关键词，优先同类型同难度。

agent 派发优先级：

1. 用户点名或页面已经暴露问题、但尚未进入 `needs_rework` 的关键词
2. 高频引用词
3. 多期词
4. 新节目新增词
5. 单期低频词

`needs_rework` 是主整理者已经审出明确问题的条目，不再派给 agent。主整理者必须自己返修、自己复核、自己更新台账。

每个 agent 必须：

- 只改被分配的文件或分片。
- 逐词标注 `kind`。
- 读取相关 `content/episodes/EPxxx.json`。
- 能查到来源就补来源；查不到不编事实，写成节目归因或标 `待核` 风险。
- 输出修改文件、节目依据、来源情况、疑点和自检结果。

## 主动检查清单

每个关键词主审时主动检查这些点，不等用户指出：

1. 类型是否正确：页面标题实际承载的是人、地点、机构、产品、事件、机制、概念、主题、资产还是常规词。
2. 基础说明是否有效：不了解这个词的人能否看懂它是什么，而不是只看到站内维护语言。
3. 节目关联是否具体：是否说清哪期节目用这个词讲了什么材料，再归纳它进入哪条问题线。
4. 延展阅读是否有逻辑：是否说明为什么能继续看某个节点，而不是只堆相邻词。
5. 常见场景是否有信息关联：是否写出“场景/信号 + 判断含义”，避免“当 A 与 B 同时出现时”反复套句。
6. 事实和节目判断是否分开：外部事实有来源，节目观点有归因。
7. 现代事实是否核对：现任、离任、死亡、破产、封禁、战争进展、监管处罚、股权变化等不能凭记忆写死。
8. 是否残留禁用表达：`为什么重要`、`使用边界`、`相关节点`、`进一步追问`、`关联信息`、`节目中的线索`、`理解信号`、`识别信号`。
9. 是否残留内部审稿口吻：`站内保留`、`节目保留`、`这个词条`、`本词条`、`候选入口`、`厚词条`、`未在本轮复核` 这类话必须删掉或改成读者向说明。
10. `programAssociations[].episodes` 是否全部出现在顶层 `episodes`，相关节目区是否能显示这些期数。
11. 是否重复：`summary`、`description`、类型专属字段、`programAssociations` 之间不能同一句换说法。
12. 页面是否显示：字段写入后前端是否真的展示；如果字段不会展示，要么改前端，要么不要用它承载关键信息。
13. 是否残留占位内容：任何 `待补充`、`暂无`、`后续补充` 都必须删除、补实或隐藏，不允许作为页面内容留给用户。
14. 是否残留时效口吻：正文不得出现“截至某日核对 / 截至本次核对 / 页面整理时”；日期只能出现在 `asOf` 或来源核对说明里。

## 类型边界与评分标准

每个关键词满分 100。主审低于 80 分退回返修；80-89 分可视风险标为 `accepted_with_known_limit`；90 分以上标为 `reviewed`。

### 人物 `person`

边界：标题承载的是一个真实人物、历史人物、公众人物、创作者、企业家、政治人物或学者。人物页不是八卦页，也不是只写节目观点。

必写结构：`summary`、`description`、`basicIntro`、`programRole`、`programAssociations`、`styleNotes`、`methodNotes`、`extensionNotes`、`sources`、`episodes`。

评分：

- 基础身份 25：是否写清是谁、关键身份/职务/时代位置；现代人物是否有 `asOf` 和来源。
- 节目关联 25：是否逐期说明节目怎样使用这个人，而不是只列 EP 或抽象归纳。
- 风格与方法 20：是否写出稳定的个人风格和行动方式，避免空泛褒贬。
- 延展阅读 15：是否能从这个人延展到制度、产业、地缘或文化问题线。
- 事实可信度 15：来源是否足够，争议事实是否克制归因。

已通过基准：`特朗普`。它明确写出第45任与第47任总统、节目关联分成美国战略/通道命门/石油美元/盟友分工，并把个人风格和方法写成可理解的政治方式。后续人物不能复制句式，但要达到这种“基础事实 + 节目关联 + 延展”的厚度。

返修信号：没有关键身份、只有一个弱来源、节目关联不提具体 EP 内容、残留 `signalNotes`、同一判断重复三次。

### 地缘/地点 `geography`

边界：国家、地区、城市、海峡、航线、港口、边界节点等，重点在地图位置、制度位置、通道和规则。

评分：

- 基础位置 25：说明它在哪里、是什么政治/地理对象。
- 规则/通道作用 25：说明它影响谁的运输、安全、金融、能源或制度边界。
- 节目关联 25：节目具体如何用它解释地缘问题。
- 常见场景 15：护航、保险、港口、边界、联盟、制裁、贸易等信息如何关联。
- 延展阅读 10：能自然接到相邻国家、海峡、制度或主题。

返修信号：写成旅游百科；只说“重要地缘节点”；没有说明谁承担成本、谁获得规则权。

### 公司/机构/平台 `organization`

边界：公司、政府机构、平台、大学、医院、基金、媒体账号或品牌咨询公司。机构页不等于事件页。

评分：

- 组织身份 20：它是什么机构，业务/权力/公共位置在哪里。
- 现实结构 25：商业模式、监管关系、治理问题或公共后果是否讲清。
- 节目关联 25：节目借它讲了什么案例。
- 暴露问题 15：它暴露了产业、组织、权力或反馈机制的什么问题。
- 来源与延展 15：现代机构有可信来源，延展到相邻企业/制度/事件。

返修信号：只写工商介绍；把机构强行写成人物；机构和事件边界混乱。

### 产品/品牌/技术对象 `product`

边界：具体产品、品牌、技术路线、车、电池、AI 内容形态、平台工具等。

评分：

- 对象说明 20：是什么产品/技术/品牌。
- 使用场景 20：谁用、在哪用、解决什么或制造什么问题。
- 现实后果 25：规模化后产生的安全、成本、平台、监管或产业影响。
- 节目关联 25：节目怎样把它放进具体案例。
- 延展 10：能接到相邻技术、企业、模型或主题。

返修信号：参数评测化；只写营销话术；没有讲用户风险或产业后果。

### 事件/战事/风波 `event`

边界：稳定命名的事件、战争、政策节点、争议风波。不是每个公司问题都单独拆成事件。

评分：

- 基本事件 25：时间、参与方、发生了什么。
- 冲突结构 25：利益、权力、制度或资源冲突是什么。
- 节目关联 25：节目用这个事件说明什么问题。
- 后续影响 15：事件如何改变规则、预期、关系或风险。
- 来源 10：现代事件必须有可信来源或明确节目归因。

返修信号：新闻流水账；只写结果不写冲突；用外部知识把节目没讲的事件写得过满。

### 机制词 `mechanism`

边界：节目用来解释因果链、运作方式或系统循环的词。它回答“事情怎样运转”。

评分：

- 直观定义 20：普通读者能懂。
- 运作链条 30：输入、过程、输出、谁承担风险。
- 节目场景 25：具体节目中的案例如何体现这个机制。
- 常见场景 15：哪些信号说明机制在发生。
- 延展 10：接到相关模型、概念或案例。

返修信号：只写抽象名词解释；没有过程；没有风险承接方。

### 概念词 `concept`

边界：解释一个想法、判断、社会现象或理解角度。它回答“这个词是什么意思，为什么这样理解”。

评分：

- 概念定义 25：直观、准确、非黑话。
- 边界区别 20：和相邻概念、机制或主题的区别是什么。
- 节目用法 25：节目如何使用这个概念理解现实。
- 常见场景 15：读者在哪里会遇到它。
- 延展 15：继续读哪些节点能加深理解。

返修信号：写成机制链；只说“用来理解”；没有概念边界。

### 主题词 `theme`

边界：跨期问题线，能组织多期节目，不是普通标签。

评分：

- 主题定义 20：这条主题线在问什么问题。
- 跨期组织 35：哪些节目怎样组成同一条线，不能只列期数。
- 观察维度 20：读者沿主题看时应该比较什么。
- 延展 15：能接到概念、模型、人物、关键词。
- 边界 10：说明不包括什么，避免主题泛化。

返修信号：只有 1 期却硬写主题；把普通关键词包装成主题；没有跨期递进。

### 金融资产/大宗商品 `asset`

边界：黄金、白银、比特币、石油美元、铜等资产/商品/信用参照物。

评分：

- 资产说明 20：是什么资产/商品/结算对象。
- 现实角色 25：价格、信用、避险、结算、平台或流动性作用。
- 风险结构 25：谁承担托管、杠杆、平台、波动、流动性或结算风险。
- 节目关联 20：节目怎样使用它解释现实。
- 非投资建议 10：不能给买卖建议，事实、节目判断和投资风险要分开。

返修信号：写成投资攻略；只说“避险”；不写平台和风险承接。

### 常规词 `general`

边界：不适合归入上述类型，但仍有明确节目语境和阅读价值的词。

评分：

- 基础含义 25：词本身讲清楚。
- 节目语境 30：为什么节目要单独拎出来。
- 常见搭配 20：和哪些场景/信息一起出现。
- 延展 15：能接到相邻线索。
- 类型合理性 10：确认不是懒得分类才塞进 `general`。

返修信号：`general` 被当成低质量兜底；只写“相关讨论对象”；没有具体节目语境。

## 审核规定

1. agent 自检不等于通过。主整理者必须按评分标准审。
2. 每批至少抽查 30%；如果抽查发现事实错误、模板空话或节目关联不成立，本批全体进入 `needs_rework` 或扩大抽查到 100%。
3. 用户点名过的问题词必须 100% 主审，包括但不限于：特朗普、户晨风、西贝、华与华、新加坡、霍尔木兹、关键词相关节目区。
4. 单期低频词允许 `accepted_with_known_limit`，但必须写清限制：例如“节目只轻触，外部事实待核，先作为候选入口”。
5. 现代人物和现代机构只要页面写出现任、离任、封禁、破产、收购、处罚、死亡、战争进展，就必须有来源或明确归因；没有来源不能通过。
6. 页面显示和数据都要审。只在 JSON 里写好但前端不展示，不算通过。
