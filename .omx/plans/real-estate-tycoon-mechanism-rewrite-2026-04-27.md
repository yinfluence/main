# 房地产大亨模拟器机制重构计划

日期：2026-04-27

## 1. 当前问题判断

现在的版本本质还是“事件选择题”：

- 玩家每回合只能回答系统抛来的题，主动经营感不足。
- 买地、贷款、预售、还债、套现、找关系、保交付这些核心行为没有成为玩家主动按钮。
- 事件池虽然变多，但事件仍然像“下一题”，不是经营过程中打断玩家计划的突发事件。
- 晋级和降级太像自动结算，玩家没有“我要不要扩张、要不要升桌、要不要拒绝更大牌桌”的选择。
- 项目账本在显示项目，却没有让项目成为行动对象：玩家不能主动选择这个项目赶工、预售、卖掉、抵押、补监管户、维修。
- 资金链没有形成完整循环：土地 -> 抵押/贷款 -> 施工 -> 预售 -> 监管户/自由现金 -> 再拿地 -> 债务滚动。
- UI 上如果继续塞题目和解释，字会越来越多，玩法会越来越重。

核心结论：

下一版不能继续把“问题库”当主游戏。要改成“玩家经营回合 + 突发事件打断 + 长期暗线结算”。

## 2. 同类型游戏参考结论

这次不能只参考传统网页，也不能只参考问答游戏。更接近的类型是：

- 少按钮高后果的决策游戏。
- 文字叙事 + 长期变量的模拟游戏。
- 资源经营 + 突发事件的桌面式游戏。
- 角色身份受限的信息游戏。

### 2.1 Reigns：少按钮，但每一下都有长期后果

参考点：

- 一屏只处理一个决策。
- 操作极少，但背后影响多个资源。
- 不告诉玩家完整后果，只给大方向。
- 没有完美答案，玩家是在短期平衡和长期死亡之间摇摆。

可借鉴：

- 我们不能给玩家一排 7 个按钮。
- 玩家每回合最多看到 3 个经营动作。
- 每个动作都要影响多条线：资金、项目、关系、安全、暗线。
- 选择后不弹详细加减，影响沉到后台，最后结算解释。

不能照抄：

- Reigns 是二选一，我们这个题材不能只有左右滑，因为房地产经营有“主动做事”的感觉。
- 我们要的是“少量动作卡”，不是“是/否判断题”。

参考链接：

- https://www.reignsgames.com/

### 2.2 Fallen London：常规行动和机会牌分离

参考点：

- 玩家平时做的是 Storylets，也就是当前地点/状态下可做的行动。
- 机会牌是随机出现的事件，不是全部主线。
- 有些机会牌可以忽略，有些是强制事件。
- 玩家位置、状态、物品、历史变量会改变能看到的行动。

可借鉴：

- 我们的“经营动作”应该像 Storylets：玩家主动选择做什么。
- 我们现在的问题库应该降级成“机会牌/突发事件”。
- 突发事件不是每回合都有，也不是固定顺序。
- 同一个玩家因为项目、关系、债务不同，会抽到不同事件。

在本游戏里的对应关系：

- Storylets = 本回合可做经营动作。
- Opportunity Cards = 突发事件。
- Attributes/Qualities = 资金、项目、关系、安全、暗线、人脉对象状态。
- Location = 当前规模/城市/周期阶段。

参考链接：

- https://fallenlondon.wiki/wiki/Cards
- https://fallenlondon.wiki/wiki/Beginner%27s_Guide

### 2.3 Cultist Simulator：行动槽 + 资源对象

参考点：

- 玩家不是从菜单里点一堆功能，而是把资源放进行动槽。
- 资源会被消耗、转化、污染、锁定、过期。
- 风险不是一个红条，而是会变成桌面上的证据、敌人、追踪者。
- 玩家能暂停思考，但系统会让后果继续发酵。

可借鉴：

- 项目、贷款、商票、监管户、关系人、证据包，都应该是可被系统追踪的“对象”。
- 玩家行动不只是数值加减，而是让某些对象变状态。
- 例如：
  - “总包证据包”不是 -5 安全，而是一个后续会被总包、媒体、住建、法院使用的对象。
  - “城投小股进入”不是 +10 现金，而是一个带来缓冲、控制权下降、政治绑定的对象。
  - “商票滚供应商”不是 +5 现金，而是一个带到期、贴现、挤兑风险的对象。

不能照抄：

- 本游戏不要做实时拖卡，移动端会复杂。
- 但可以借它的“对象会留在桌上、后续被事件抓取”的机制。

参考链接：

- https://en.wikipedia.org/wiki/Cultist_Simulator

### 2.4 Suzerain：不是全知系统，而是坐在权力位置上的有限信息

参考点：

- 玩家通过部长、顾问、部门、家人和派系获得信息。
- 信息不是全透明的，每个人都有立场。
- 决策有政治、经济、家庭、安全等多重后果。
- 结局页总结玩家路线和统计结果。

可借鉴：

- 房地产商不应该看到完整上帝视角。
- 玩家看到的是银行、政府、总包、业主、竞争对手分别怎么说。
- 同一个事实会被不同人解释成不同意思。
- 最终结算不是“你选错了”，而是“你听信了谁、牺牲了谁、把风险转给了谁”。

在本游戏里的对应关系：

- 部长/顾问 = 财务、项目总、法务、渠道、政府口、银行口。
- 派系 = 政府部门、银行、总包、业主、竞争对手、国资、灰色关系。
- 国家路线 = 房企经营路线：高周转、稳健交付、关系信用、财技滚动、国资绑定、高点退出。

参考链接：

- https://en.wikipedia.org/wiki/Suzerain_%28video_game%29

### 2.5 80 Days：路线不是线性题库，而是碎片根据位置和历史拼接

参考点：

- 玩家选择路线，故事片段会根据去过哪里、带着什么、花了多少时间拼接。
- 时间、钱、疲劳持续压迫玩家。
- 不是所有内容都一局出现，所以重玩会有新路线。

可借鉴：

- 我们不能让玩家每局都遇到同样事件。
- 县城、城市、省会、全国，每个“位置”有自己的事件池。
- 周期阶段也像地图：上行、棚改、三道红线、保交楼，每个阶段事件不同。
- 玩家带着某些旧账进入新阶段，会改变后面抽到的事件。

参考链接：

- https://intfiction.org/t/announcing-80-days-for-ios/6914

### 2.6 Choice of Games：选择要公平地暗示后果

参考点：

- 好选择不是让玩家猜作者想法。
- 选项应该传达大致效果。
- 每个选择要有困难权衡。
- 属性和统计应该服务主题，不应该只是装饰。

可借鉴：

- 按钮文案要暗示代价，但不要显示精确加减。
- 每个按钮都要让玩家知道自己大概在牺牲什么：
  - “快回款”通常牺牲价格、品牌、业主预期。
  - “找政府”通常增加政治绑定和被安排任务的风险。
  - “找银行”通常增加抵押、利息、信息披露。
  - “压总包”通常增加反咬和停工风险。
- 结算页解释不是为了训玩家，而是回放机制。

参考链接：

- https://www.choiceofgames.com/contest/

### 2.7 参考后的总原则

最终采用的方向：

- 前台要像 Reigns 一样少按钮。
- 常规行动和突发事件要像 Fallen London 一样分离。
- 项目、贷款、人情、证据要像 Cultist Simulator 一样成为可追踪对象。
- 人物信息要像 Suzerain 一样有立场、有偏差、有代价。
- 路线拼接要像 80 Days 一样根据位置、时间、历史变量变化。
- 选择表达要像 Choice of Games 标准一样，让玩家能看出大致代价，但不能看穿全部结果。

## 3. 按钮不能平铺：采用“动作槽 + 行动池”设计

你说的对：如果把“拿地、融资、推进项目、找关系、回款套现、降风险、退出”全部做成常驻按钮，界面会变成管理后台，不像游戏，也会让移动端崩掉。

所以这里要分两层：

- 后台：有很多行动类型。
- 前台：每回合只显示 3 个，极少数危机回合显示 4 个。

玩家看到的不是分类按钮，而是具体动作。

错误方式：

- 拿地
- 融资
- 推进项目
- 找关系
- 回款
- 降风险
- 退出

这种太像软件菜单，玩家不知道点哪个，也没有剧情感。

正确方式：

- 用东郊项目抵押，找县支行加一笔开发贷
- 让河湾 2 号地提前开盘，先把首批按揭打回来
- 拿下南站地块保证金，但把工程款往后压一周

这三个按钮背后分别属于融资、回款、拿地，但玩家不需要看到分类。

### 3.1 前台按钮数量

普通经营回合：

- 固定 3 个按钮。

危机回合：

- 3 个按钮。
- 如果危机很复杂，最多 4 个。

突发事件回合：

- 固定 3 个按钮。

规模评审回合：

- 固定 3 个按钮：
  - 接受升桌
  - 暂缓扩张
  - 主动收缩/退出

永远不要超过 4 个。

## 2026-04-27 追加修正：底部经营图标与融资现金逻辑

这次用户指出两个硬问题：

- 玩到后面图标消失，说明“经营桌面”和“突发事件”切换还是两套 UI。
- 贷款动作让现金降低，说明融资效果和同回合付息/项目滚动互相打架。

修正原则：

- 底部图标是经营入口，不是某一页的装饰；普通经营、压力事件、高压事件都要保留。
- 只有真正危机事件可以暂时锁住底部入口，因为这种事件必须先处理。
- 图标必须是真图标，不再用“地/钱/楼/售/人/险”文字冒充图标。
- 融资动作要符合基本经济逻辑：贷款/授信/展期先带来自由现金，代价是债务、抵押、利息、银行穿透和后续展期压力。
- 新融资本轮不应马上被同一笔融资的利息吞掉；利息和展期压力应该从后续回合体现。

落地修改：

- `renderActionDock()` 改为 SVG 图标底部动作栏。
- 非办公室事件页也渲染底部经营入口和资产桌面。
- 在非危机突发事件中点击经营图标，会把当前事件压到下一轮并增加少量风险，而不是让图标消失。
- `recordFundingFromChoice()` 记录本轮新增融资本金。
- `advanceFundingLedger()` 对本轮新融资做付息宽限，不让新钱在同一回合被自己产生的利息吃掉。
- `preserveFreshFinancingCash()` 保证融资动作至少保留一部分现金到账效果；后续风险通过融资账本、展期、银行压力和结局解释体现。

## 2026-04-28 追加修正：办公室页不能同时有图标栏和地图

用户指出截图里的问题是对的：上面一排“土地/资金/项目/销售/关系/安全”图标，和下面“土拍大厅/支行后门/工地门口/饭局包间”等地点，本质上都是入口。两个入口同时存在，会让玩家不知道自己是在点功能，还是在地图里选地点。

新的 UI 规则：

- 老板办公室页只保留“城市地图”作为主入口。

  - 老城、新区、东郊、南站等区域。

  - 土拍、支行、工地、售楼、饭局、法务作为可点击地点。
- 玩家点击地点后，下面才出现这个地点当前能做的几件事。
- 功能图标栏不再出现在办公室页，避免重复导航。
- 图标栏如果保留，只能作为非办公室突发事件页的快捷入口；普通经营页必须以地图为准。
- 地图节点只放极短文字：地点名、区域名、窗口数量；不要再放长说明。
- 项目账本放到地图后面，作为“手里项目”，不要抢主操作入口。

- 地图底图加入河道、道路、城区标签。
- 选中地点后只显示该地点动作池，形成“先去哪里，再做什么”的操作节奏。

## 2026-04-28 追加修正：土地页必须是真土拍地图，不是买地按钮

用户继续指出：土拍不是“点一下土地就买”，而是应该进入一张城市土地地图。地图里要同时看到：

- 玩家已经拿到的地。
- 本轮可竞拍的地。
- 哪些地是自己的，哪些是土拍窗口。
- 点一块地以后，才显示这块地的面积、起拍价、保证金、竞争强度和竞标方式。
- 后期随着等级上升，能看到的地块大小、价格、竞争强度都要变大。

新的土拍规则：

- 老板桌面仍保留 4 个主桌：土地、资金、项目、关系。
- “项目”合并销售，因为预售、渠道、交付和回款本来是一张项目桌。
- “关系”合并安全，因为法务、切割、退出、反咬都离不开关系和人性风险。
- 点击“土地”不再显示普通动作列表，而是显示 `land-market-map`：
  - 绿色/自有 = 已拿地块。
  - 红色/土拍 = 本轮可竞拍地块。
  - 点击自有地显示该地估值、阶段和回款状态。
  - 点击土拍地显示竞拍详情和 3 种竞标打法。
- 土拍地块由当前等级生成：
  - 无名小老板：边缘小地，价格低、面积小、竞争低。
  - 县城开发商：县城地块，开始出现老城/南站。
  - 城市新贵：城市核心地，价格和竞争明显上升。
  - 区域房企/全国百强/帝国：大盘、资产包、核心区地块，价格和风险同步放大。
- 竞标不是必成：
  - 压线举牌：成功率低一些，现金和旧账损耗小。
  - 跟到上限：成功率高一些，但债务、利息、对手压力更高。
  - 饭局口探底/联合体进场：成功率较高，但会增加权力依赖、代持/围标/倒查风险。
- 成功后才把地加入项目账本；失败也会损耗保证金、关系和对手压力。

落地修改：

- 新增 `auctionDesk`、`selectedAuctionLotId`、`selectedProjectId` 存档字段。
- 新增 `AUCTION_SCALE_PROFILES`，用当前规模控制可竞拍地块的面积、价格和竞争强度。
- 新增 `generateAuctionLots()`、`renderLandDesk()`、`resolveAuctionBidAction()`。
- `applyProjectLedgerFromChoice()` 支持用竞拍地块的真实标题、估值、可售货值、质量、预售/交付周期生成项目。
- 办公室页隐藏独立项目账本，把项目/土拍信息放进地图。
- 移动端压缩为一页：顶部四个状态 + 地图 + 短详情 + 最多 3 个竞标按钮。

验证：

- 移动端办公室页首屏只有 4 个主桌入口：土地、资金、项目、关系。
- 点击土地后出现 `land-market-map`。
- 地图里至少有 1 个自有地块和 3 个土拍地块。
- 点击土拍地后出现 3 个竞标方式。
- 选中土拍地后的移动端页面高度低于 760px 视口，不需要上下反复移动。
- 验证截图：`.local/real-estate-land-auction-mobile.png`

### 3.2 三个按钮的来源

每回合由系统从行动池里挑 3 个“动作槽”。

动作槽 A：机会槽

- 目的：赚钱、扩张、拿地、开盘、套现。
- 例子：
  - “用预售回款交下一块地保证金”
  - “趁房价上行，把河湾 2 号地提前开盘”
  - “把成熟项目打包卖给本地国企”

动作槽 B：压力槽

- 目的：处理当前最危险的问题。
- 例子：
  - “找银行展期，先保住本月现金”
  - “补监管户，换住建口不发红函”
  - “给总包一笔节点款，别让工地停”

动作槽 C：布局槽

- 目的：关系、安全、长期能力、退出准备。
- 例子：
  - “让城投小股进入，换一个政府缓冲”
  - “清理商票和发票链，先把旧账压低”
  - “拒绝新地，先把第一盘交出去”

动作槽 D：特殊槽

- 只在特殊条件出现。
- 用于：
  - 高点退出
  - 升桌
  - 危机卖资产
  - 被迫重组
  - 法律/扫黑/监管处置

特殊槽出现时，可以替换掉机会槽或布局槽，但总按钮数不增加。

### 3.3 行动池分类只存在后台

后台行动池仍然要分细：

- land：拿地、保证金、联合拿地、卖地。
- finance：贷款、展期、抵押、商票、信托、过桥。
- project：赶工、保质量、预售、交付、维修、换总包。
- relation：政府、住建、自然资源、银行、城投、业主、总包。
- sales：开盘、降价、渠道、样板间、尾盘、资产包出售。
- safety：清账、补证据、切割灰线、资产隔离、退出。

但这些分类不直接显示给玩家。

显示给玩家的一定是“当前局面下真实会发生的动作”。

### 3.4 按钮筛选规则

每回合按照以下顺序筛选：

1. 先判断有没有红线。
   - 现金红：压力槽优先融资、卖资产、催回款。
   - 项目红：压力槽优先赶工、补监管户、找住建、安抚业主。
   - 关系红：压力槽优先政府、银行、城投、总包关系修复。
   - 安全红：压力槽优先清账、切割、法律处理、退出。

2. 再判断有没有机会。
   - 房价上行：机会槽优先拿地、开盘、抵押增贷。
   - 销售热：机会槽优先预售、渠道、涨价/控盘。
   - 银行关系好：机会槽优先授信、开发贷。
   - 政府关系好：机会槽优先联合拿地、政策项目、城投合作。

3. 再判断有没有长期隐患。
   - 总包忍耐低：布局槽给安抚总包或换总包。
   - 商票高：布局槽给清票或展期。
   - 黑灰高：布局槽给切割或补证据。
   - 业主信任低：布局槽给开放工地、延期补偿、质量维修。

4. 最后判断是否出现特殊槽。
   - 资产大涨 + 风险可控：可能出现“套现离场”。
   - 规模达标：可能出现“升桌机会”。
   - 连续现金红：可能出现“债务重组/项目甩卖”。
   - 安全破线：可能出现“被调查/停职/刑事风险处置”。

### 3.5 按钮文案规则

按钮不能写成抽象功能。

不要写：

- 融资
- 找关系
- 推进项目
- 降风险

要写：

- 找支行林经理，把东郊地块重新估值
- 让总包先进场，签证以后再算
- 接受城投小股，换预售许可往前走
- 降价清一批尾房，先把商票兑了
- 把土方老板切干净，但准备他反咬

按钮上不显示具体数值加减，只显示轻量提示：

- 需要现金
- 会压关系
- 会留旧账
- 能快回款
- 能保交付
- 有反噬

### 3.6 一回合示例

场景：

- 早期扩张。
- 房价上行。
- 东郊第一块地进入预售。
- 现金偏紧但还没红。
- 银行关系尚可。
- 总包忍耐下降。

前台显示 3 个按钮：

1. “用东郊预售数据找支行加授信”
   - 后台分类：finance。
   - 好处：现金、授信、拿地空间上升。
   - 代价：债务、利息、抵押约束上升。
   - 随机：银行关系越高越容易批，监管户异常会降低成功率。

2. “趁房价热，把河湾 2 号地保证金交了”
   - 后台分类：land。
   - 好处：新增项目、资产、未来货值。
   - 代价：现金下降、项目压力上升、交付链拉长。
   - 随机：政府关系和竞争对手会影响地价。

3. “先给总包一笔节点款，别让他停工”
   - 后台分类：project/relation。
   - 好处：工程推进、总包忍耐回升。
   - 代价：现金下降，其他债务更紧。
   - 随机：如果总包已经留证据，安抚效果会打折。

玩家看到的是三件真实事，不是七个系统菜单。

### 3.7 为什么这样更像游戏

这个结构的好处：

- 每回合只有 3 个选择，移动端能看清。
- 每个选择都具体、有画面、有当事人。
- 玩家不会在菜单里迷路。
- 后台仍然能覆盖拿地、融资、项目、关系、回款、退出。
- 系统能根据局面自动把最重要的线索推到前台。
- 玩家会觉得自己在经营，而不是答题。

这也解决了“问题变成突发事件”的要求：

- 平时玩家主动经营。
- 事件只是打断经营节奏。
- 事件不是主菜，而是经营后果的回声。

## 4. 目标形态

玩家每回合不是回答一道题，而是在老板办公室做经营决策。

每回合结构：

1. 回合开始结算
   - 项目自动推进工程进度。
   - 在售项目产生销售、按揭回款、监管户沉淀、自由现金。
   - 银行贷款、信托、商票、过桥资金产生利息或到期压力。
   - 房价、销售热度、地方政策、竞争环境按周期变化。

2. 老板台面展示
   - 只显示 4 个核心状态：资金、项目、关系、安全。
   - 下方用极简项目账本显示 1-3 个最关键项目。
   - 详细账本隐藏到抽屉，不默认铺开。

3. 玩家主动选择经营动作
   - 每回合最多显示 3-4 个主按钮。
   - 按钮不是“答案”，而是实际经营动作。
   - 例如：拿地、贷款、赶工、预售、找住建、找银行、找城投、卖资产、还债、补监管户、处理业主、换总包。

4. 动作结算
   - 每个动作不是固定结果，而是一个概率范围。
   - 同一个动作根据现金、关系、项目质量、周期、历史暗线，结果会不同。
   - 例如找银行贷款：银行关系高、抵押物升值、销售好时更容易成功；关系低、监管户有问题、利息高时可能被抽贷或要求担保。

5. 突发事件检查
   - 系统根据暗线和概率，决定是否插入突发事件。
   - 突发事件才是现在那些“问题/剧情”的位置。
   - 突发事件不是每回合都有，但一旦出现要紧、具体、有冲击。

6. 晋级/降级/退出检查
   - 不允许“点一下晋级，下一个选项降级”。
   - 晋级变成“规模跃迁机会”，玩家可以接受、观望、拒绝。
   - 降级变成连续危机后的强制收缩、项目处置、债权人接管，而不是普通选项后立刻降。

## 5. 主循环设计

### 5.1 回合类型

每一回合分成四类之一：

- 经营回合：默认，占多数。玩家主动选择经营动作。
- 突发事件回合：由暗线触发，占少数。玩家必须处理事件。
- 规模评审回合：满足条件后出现。玩家选择是否扩张、稳住、退出。
- 危机处置回合：现金、交付、法律、安全破线后出现。玩家选择卖资产、求国资、债务展期、停工重组等。

### 5.2 经营回合按钮

每回合最多 3 个按钮，危机回合最多 4 个按钮，从后台行动池里按当前状态生成。

注意：下面这些是后台分类，不是前台常驻按钮。玩家不应该同时看到所有分类。

土地类：

- 拍下一块地
- 跟踪地块，不交保证金
- 联合城投/国企拿地
- 放弃地块，保现金
- 卖掉边缘地块

融资类：

- 找银行加授信
- 用项目抵押贷款
- 找信托/私募过桥
- 开商票给供应商
- 谈展期
- 提前还一部分短债

项目类：

- 加快施工
- 保质量慢施工
- 提前预售
- 补监管账户
- 处理交付节点
- 维修已交付项目
- 换总包/分包

关系类：

- 找县领导协调
- 找住建口协调预售/验收
- 找自然资源口看地
- 找银行行长/授信经理
- 找城投/国资合作
- 安抚业主代表
- 安抚总包/供应商

销售/现金类：

- 加大渠道投放
- 降价回款
- 保价等待
- 做样板间/营销包装
- 打包卖项目
- 套现成熟资产

安全/退出类：

- 公开账本补证据
- 切割灰色关系
- 清理票据和税务
- 家族资产隔离
- 主动收缩
- 高点退出

### 5.3 按钮生成规则

不是每回合都展示所有按钮。

生成逻辑：

- 普通经营回合只给 3 个最合理动作。
- 危机回合最多给 4 个动作。
- 至少 1 个动作来自“最急问题”。
- 至少 1 个动作来自“玩家扩张/赚钱机会”。
- 至少 1 个动作来自“风险缓释/稳住”。
- 如果现金很紧，优先给融资、卖资产、催回款、展期。
- 如果项目逾期，优先给赶工、补监管户、找住建、处理业主。
- 如果关系弱，优先给政府/银行/国资/地方协调。
- 如果市场上行，增加拿地、加杠杆、预售、扩团队。
- 如果市场下行，增加降价、卖项目、债务重组、国资接盘、退出。
- 如果出现升桌机会，用“规模评审页”替换普通经营回合，不插在普通按钮里。
- 如果出现高点退出机会，用特殊槽替换一个普通动作，不额外增加按钮。

## 6. 项目系统重构

每个项目都要成为真实经营对象。

### 6.1 项目生命周期

项目阶段：

1. 土地
2. 报批报建
3. 在建
4. 可预售
5. 预售回款
6. 交付冲刺
7. 已交付
8. 售后/返修/旧账
9. 处置/出售/烂尾/国资接管

### 6.2 项目字段

每个项目至少有这些字段：

- 地块名
- 所属城市/县区
- 阶段
- 土地成本
- 账面估值
- 可售货值
- 已售金额
- 自由现金回款
- 监管户沉淀
- 工程进度
- 质量水平
- 交付期限
- 项目债务
- 抵押状态
- 政府绑定程度
- 业主信任
- 总包关系
- 历史隐患

### 6.3 项目收益逻辑

拿地不是立刻赚钱。

正确链条：

1. 拿地消耗现金或增加债务。
2. 土地估值随房价周期变化。
3. 估值上涨后，银行抵押空间增加。
4. 达到预售条件后，开始销售。
5. 销售带来总回款。
6. 总回款拆成：
   - 自由现金
   - 监管户
   - 必须用于工程的资金
   - 后续交付责任
7. 项目进入交付后，未完成责任会变成业主、住建、银行和法律风险。
8. 已交付项目不默认消失，低概率在后期返修、质量、物业、老业主维权中回来。

### 6.4 多项目滚动

关键机制：

玩家不应该等第一个项目交付才拿第二块地。

当满足以下条件时，系统应该推送扩张机会：

- 项目进入预售或回款阶段。
- 房价指数上行。
- 银行信任足够。
- 政府关系没有太差。
- 现金池不是红线。
- 现有项目没有严重失控。

此时出现经营按钮：

- 用预售回款交下一块地保证金
- 用抵押物增值申请银行授信
- 组第二支项目队伍
- 联合城投拿地
- 拒绝扩张，先交付当前项目

这才是房地产开发商的真实循环。

## 7. 资金系统重构

### 7.1 资金来源

资金来源分成几类：

- 自有现金
- 银行开发贷
- 按揭回款
- 预售款
- 信托/私募/过桥
- 商票
- 供应商垫资
- 城投/国资合作资金
- 项目出售/套现
- 家族/关联方资金

### 7.2 资金成本

每类钱都有代价：

- 银行钱：利息较低，但要看抵押、回款、监管户、政府关系。
- 信托/私募：速度快，利息高，容易变成个人担保和法律风险。
- 商票：短期保现金，后期供应商挤兑。
- 预售款：不是自由现金，带有交付责任和监管户约束。
- 城投资金：缓冲强，但控制权、处置权和政治绑定上升。
- 项目出售：能回现金，但可能被债权人、政府、竞争对手压价。

### 7.3 玩家可做的资金动作

经营按钮里要出现：

- 申请开发贷
- 抵押土地增贷
- 用预售款补工程
- 补监管户
- 商票续供应商
- 信托过桥
- 债务展期
- 卖项目还债
- 国资小股进入
- 主动降杠杆

## 8. 关系系统重构

### 8.1 关系对象

关系不是一个总分，要拆成对象：

- 县领导/地方政府
- 自然资源局
- 住建局
- 银行行长
- 授信经理
- 城投/国资
- 总包老板
- 供应商
- 渠道公司
- 业主代表
- 竞争对手
- 土方/灰色关系
- 税务/环保/监管卡口

### 8.2 每个对象有状态

每个关系对象至少有：

- 信任度
- 忍耐度
- 利益绑定
- 被切割风险
- 反咬概率
- 能提供的帮助
- 可能制造的麻烦

### 8.3 联系人动作

玩家可以主动联系不同人/部门。

例子：

- 找银行：贷款、展期、抵押重估、监管户拨付。
- 找住建：预售许可、验收、白名单、保交楼协调。
- 找自然资源：看地、保证金、土拍条件。
- 找城投：联合拿地、国资小股、项目接盘。
- 找总包：赶工、签证、垫资、停工风险。
- 找业主代表：开放工地、延期补偿、维权降温。
- 找渠道：促销、返佣、刷流水、渠道反咬。

每个联系动作都要有利弊：

- 找政府可能解决审批，也会增加政治绑定。
- 找银行可能解决现金，也会增加利息和抵押约束。
- 找总包可能赶工，也会增加签证和质量风险。
- 找城投可能救命，也会让控制权变弱。

## 9. 突发事件重构

现在的事件池要降级为“突发事件池”。

突发事件来源：

- 银行：抽贷、换行长、监管户卡住、授信重估。
- 政府：约谈、停工、土拍窗口、价格管控、保交楼专班。
- 项目：暴雨、质量、进度、塔吊、安全、地下车库、返修。
- 业主：直播、律师函、停贷威胁、老业主降价维权。
- 总包：证据包、停工、签证、工资专户、商票贴现。
- 供应商：停供、涨价、商票折价。
- 竞争对手：举报、航拍、价格战、渠道挖人。
- 黑灰线：土方反咬、旧改视频、保护伞倒查。
- 税务/审计：发票链、收入确认、关联资金。
- 媒体/平台：房产号、短视频、舆论发酵。

突发事件触发规则：

- 不再按主线顺序强推。
- 每回合根据风险权重抽取。
- 同一类事件有冷却时间，避免重复疲劳。
- 风险越高，触发概率越高。
- 玩家如果长期忽视某条线，该线突发事件会越来越狠。

## 10. 晋级机制重构

### 10.1 不再自动晋级

晋级不应该是“某个选项后立刻升”。

改成：

- 系统检测玩家是否具备升阶资格。
- 满足后出现“规模跃迁机会”。
- 玩家可以选择：
  - 接受扩张，升到新桌面。
  - 暂缓扩张，继续稳当前项目。
  - 主动收缩，保现金和安全。

### 10.2 晋级看什么

晋级主要看：

- 现金池
- 项目数量
- 可售货值
- 已回款金额
- 银行关系
- 政府关系
- 交付能力
- 负债压力
- 老板安全
- 项目是否有闭合能力

### 10.3 建议晋级条件

无名小老板 -> 县城开发商：

- 至少 1 个项目进入预售/在建后期。
- 现金不是红线。
- 银行和政府关系不低。
- 没有重大安全或黑灰风险。

县城开发商 -> 城市新贵：

- 至少 2 个项目同时运作，或 1 个交付 + 1 个在售。
- 有稳定银行授信。
- 有一条可复制的销售/施工/政府关系链。

城市新贵 -> 区域房企：

- 至少 3 个项目。
- 至少 2 个项目产生真实回款。
- 跨县/跨城关系打开。
- 现金、债务、交付没有同时红线。

区域房企 -> 全国百强：

- 多城市项目组合。
- 融资渠道多元。
- 有评级、商票、信托、银行等复杂资金链。
- 同时要有很高风险。

全国百强 -> 地产帝国：

- 极难。
- 需要巨大资产、融资能力、政府关系和项目滚动能力。
- 同时个人安全、债务、交付、监管、舆论风险极高。

## 11. 降级和失败机制

降级不应该随机跳。

降级来源：

- 连续现金红线。
- 项目被迫出售。
- 银行授信大幅收缩。
- 政府关系破裂。
- 交付失败导致信用坍塌。
- 个人安全下降。
- 国资/债权人接管项目。

降级表现：

- 弹出“强制收缩”页面。
- 明确说明失去什么：
  - 少了几个项目。
  - 哪些资产被卖。
  - 银行额度缩了多少。
  - 政府/城投态度如何变。
  - 竞争对手如何接盘。

失败结局：

- 资金链断裂
- 债务重组失败
- 保交楼失败
- 扫黑/刑事线牵连
- 国资接盘但老板出局
- 高点离场
- 小富即安
- 区域扩张失败
- 类恒大式高杠杆崩盘
- 成为地方工具人

## 12. UI 重构计划

### 12.1 默认界面

上方：

- 身份
- 阶段
- 回合
- 4 个核心仪表：资金、项目、关系、安全

中间：

- 老板办公室/当前经营局面
- 3-4 个经营动作按钮

下方：

- 暗线风险
- 节目来源
- 历史决策链

### 12.2 按钮逻辑

按钮不能太多。

每回合按钮数量：

- 普通经营回合：3 个
- 危机回合：3-4 个
- 晋级/规模评审：3 个
- 突发事件：3 个

按钮文案要像老板真实动作：

- “找支行加授信”
- “用预售回款交保证金”
- “补监管户，先保交付”
- “让城投小股进入”

不要再像考试答案。

## 13. 内容和节目关系

节目内容不应该每题硬讲。

改成：

- 每个经营动作绑定机制标签。
- 每个突发事件绑定节目来源。
- 结算页统一复盘：
  - 你的主路径是什么。
  - 你真正的问题在哪里。
  - 哪几条暗线反复被触发。
  - 哪些节目解释了这些机制。
  - 下次应该观察什么。

游戏中只保留少量提示，不讲课。

## 15. 验收标准

必须满足：

- 刷新页面自动清空。
- 按钮点击一次执行。
- 每回合最多 4 个按钮。
- 玩家有主动动作，而不是只能回答题。
- 项目未交付时也能继续拿地。
- 项目能自然回款。
- 回款进入现金、监管户、交付责任三条线。
- 晋级不是自动跳，而是玩家选择。
- 降级不是随机跳，而是连续风险结果。
- 突发事件来自暗线，不是固定题序。
- 结算页能说清玩家问题在哪里。

## 16. 最大风险

风险 1：机制太复杂，UI 又变乱。

解决：

- 后台复杂，前台只显示 4 个状态 + 3 个按钮 + 简项目账本。

风险 2：按钮变成无意义经营菜单。

解决：

- 每个按钮必须绑定真实资源变化：现金、项目、关系、安全、暗线。

风险 3：玩家不知道为什么死。

解决：

- 结算页显示责任链，而不是只显示数值。
- 每个失败结局必须引用 3-5 个关键决策和 2-3 条暗线。

风险 4：又变成题库循环。

解决：

- 事件只作为突发事件。
- 常规回合必须来自玩家主动动作。

### 2026-04-28 交付后现金不增长问题

用户指出：

- 接了土地、项目交付以后，资金还是没有增长。
- 玩家无法理解“交付了为什么不回钱”。

代码审查结论：

- 预售和交付冲刺阶段已经会产生回款，并把一部分放进现金池。
- 交付节点也有一次结算，但会先被债务、工程款和融资顺位截流。
- 真正的缺口在于：`PROJECT_CASH_STAGES` 已经把 `delivered` 视为可回款阶段，界面也可能显示“尾盘预计”，但 `advanceProjectLedger()` 的真实入账逻辑只处理 `presale` 和 `delivery`，没有处理 `delivered`。
- 结果就是：交付后的尾盘/尾款在显示层有预期，账本层没有继续入账，玩家会感觉“房子交了，钱没回来”。

已修改：

- `projectActiveProjects()`：
  - 已交付项目如果还有剩余货值且预计能产生自由现金，会继续出现在项目列表里。
  - 不再一交付就完全归档消失。
- `projectCanCashLabel()`：
  - 已交付项目新增 `尾盘回款`、`尾款到账` 状态。
- `advanceProjectLedger()`：
  - 回款滚动阶段从 `presale/delivery` 扩展到 `presale/delivery/delivered`。
  - 已交付后的回款按尾盘逻辑处理：
    - 更低监管/维修保证比例。
    - 更高自由现金比例。
    - 不再增加保交楼压力和购房款责任。
    - 单独记入 `tailSaleCash`，不再混进 `presaleCash`。
- `maybeDeliverProject()`：
  - 降低交付结算被债务顺位完全截流的概率。
  - 如果项目有交付结算且融资压力没有极端失控，至少允许小额现金进入现金池。
