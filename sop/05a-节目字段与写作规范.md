## 节目条目字段规范

### 单期装配速查表（先看这张，再往下看各字段细则）

做一期节目，每个字段填什么、填什么键、多少字、细则去哪查，一表看全；不必为找一个字段的规则翻好几个子文件。带字数的项，build 前必须用 `sop/05b-节目导入流程与命名.md`「入库前字数自检」的脚本逐项量。

| 字段 | 填什么 / 键类型 | 字数 / 数量 | 细则位置 |
| --- | --- | --- | --- |
| `id` | `EPxxx` | — | 本节 |
| `publishedAt` | 平台真实发布时间（ISO，别填未来日期） | — | 本节 |
| `status` | `curated`（可展示）/ `draft` | — | 本节 |
| `summary` | 本期主判断 | **200–250 字** | 本节 |
| `tags` | 自然语言词；每个词都要在 `content/keywords/` 建词条 | — | `sop/01` |
| `people` | 人物中文名（以节点 `name` 为准，不以字幕口语为准） | — | 本节 + `sop/03` |
| `themes` | 中文展示名 | — | `sop/03` |
| `concepts` / `models` | 英文 slug（文件名去 `.json`） | — | `sop/03` |
| `relatedEpisodes` | `EPxxx`；从命中的 theme / concept / model 节点的 `episodes` 数组反查相关期 | 覆盖相关期 | `sop/03` |
| `topic.background` | 现实入口、为何拿它当样本 | 无硬标 | 「各字段具体怎么写」节 |
| `topic.conflicts` | 对立观点，每条一个独立判断 | 每条独立 | 「各字段具体怎么写」节 |
| `topic.boundaries` | 影射 / 归因 / 边界声明 | — | 「各字段具体怎么写」节 |
| `topic.mechanism` | 因果链，箭头用 `->`（现存主流）或 `→` | **150–250 字 / 5–6 步 / 每步 20–40 字** | 「各字段具体怎么写」节 |
| `topic.extensions` | 延展话题 | **每条 80–130 字** | 「各字段具体怎么写」节 |
| `viewpoints` | 各条独立判断（title + body） | **4–6 条 / 每条 body 80–150 字** | 「各字段具体怎么写」节 |
| `extensions`（根节点） | 读完本期的开放追问 | **每条 30–80 字** | 「各字段具体怎么写」节 |
| `videoLinks` | `platform` + `url`；会员加 `access: member` | — | `sop/02` |

**装配后必做（不属于单字段规则、但每期都要做）：**

1. 双向回写：写进 `concepts` / `models` / `themes` / `tags` 的每个节点，必须把本期 `EPxxx` 回写到对应节点文件的 `episodes` 数组（见 `sop/03a-双向引用与节点生成.md` 双向引用同步规则）——只单向引用、不回写，详情页会断链。
2. 关键词词条：`tags` 里每个词都要在 `content/keywords/` 有词条，没有就建（见 `sop/01-关键词治理.md`）。
3. 字数自检：build 前跑 `sop/05b-节目导入流程与命名.md`「入库前字数自检」脚本逐项量，超标先压再 build。
4. 分集系列（标题带“（上）/（下）”）：上下集各自独立 `EPxxx`，并把对方期号写进各自 `relatedEpisodes`；下集还没发时上集先留位，下集发布后回填。

每个节目 JSON 至少包含：

- `id`
- `title`
- `publishedAt`（节目发布日期，ISO 8601，如 `2026-06-04T12:00:00.000Z`）
- `status`（顶层状态，已整理好可展示填 `curated`，草稿填 `draft`）
- `summary`
- `videoLinks`（可选）
- `tags`
- `people`
- `themes`
- `concepts`
- `models`
- `relatedEpisodes`
- `topic`
- `viewpoints`
- `extensions`

其中：

- `publishedAt` 用平台**真实发布时间**，不要用整理日期，更不要填未来日期——填成未来日期前台会显示“即将发布”。B 站可从 `https://api.bilibili.com/x/web-interface/view?bvid=...` 的 `pubdate`（秒级时间戳）换算。
- 引用字段填 id 还是中文名：`concepts` / `models` 填英文 slug（文件名去掉 `.json`），`people` / `themes` 填中文展示名，`tags` 填自然语言词，`relatedEpisodes` 填 `EPxxx`。完整规则见 `sop/03a-双向引用与节点生成.md`「不同关联字段，用的不是同一套键」一节。
- `people` 里的人物最好有对应 `content/people/` 源节点（中文名以节点 `name` 为准，不以字幕口语为准，例如字幕说“川普”、节点 `name` 是“特朗普”就填“特朗普”）。本期重要、但还没有 person 节点的人物（例如单期首次出场的主角），先写进 `tags` 并在 `content/keywords/` 建 person 词条，`people` 字段可暂留其中文名，等多期积累后再补 `content/people/` 源节点。

- 正文中的节目引用
  - 在节目详情页、概念页、模型页、主题页、关键词页等非卡片正文里，凡是写到 `EPxxx`，前端必须渲染成可点击内链，目标为 `#/episodes/EPxxx`。
  - 网页日志是例外：日志要保留具体更新内容，但其中的 `EPxxx`、关键词和其它知识节点只显示纯文本，不做内链和浮窗。
  - 不要只把 `EPxxx` 写成纯文本；如果一个段落提到其他节目，例如 `EP057`、`EP111`、`EP128`，读者应该可以直接点过去。
  - 整张卡片本身已经是链接时，卡片摘要可以保持纯文本，避免 `<a>` 里再嵌套 `<a>` 造成点击冲突。
  - 修改此类渲染逻辑后，必须运行 `npm run build`，确认 `docs/assets/app.js` 和 `docs/data/site.json` 已同步生成；发布前还要更新网页日志。

- `summary`
  节目卡片和详情页页头那段"简介"。简介就是简介，不是当期内容压缩稿。
  - 长度区间 **200–250 个中文字符**（2026-05-26 从 250–350 收紧）。少于 200 偏单薄、读不出节目份量；超过 250 就不再是简介，是当期文字稿浓缩版。
  - 结构：**2–4 句话**。第一句交代当期切入的事件/人物/议题；中间一两句交代节目的核心论点、冲突或拆解路径（可以点出关键比喻、关键数据、关键对立面）；最后一句点出落点视角或时代判断。不要分点、不要用破折号串三个完整论证、不要把"第一/第二/第三"全段铺开。
  - 不允许塞进 `summary` 的内容（属于其它字段）：
    - 三条以上的论证拆解、机制推演 → 写进 `viewpoints`
    - 背景/冲突/边界/机制/延展五段式 → 写进 `topic.background / conflicts / boundaries / mechanism / extensions`
    - 具体数据点、案例细节、人物原话 → 写进 `viewpoints` 或 `topic.mechanism`
    - 跨期关联与延展节目 → 写进 `topic.extensions`
  - 自检：把 `summary` 单独拎出来读，应该像公众号头条摘要，**8 秒左右读完**，读者读完知道本期在谈什么、节目站在什么位置；但读不到每条数据、每个案例、每个论证细节。
  - **不许出现编辑口吻。** 「本期不接受这个说法」「这期不评艺术，只拆品牌为什么同意」「上集划了墙，本集回答谁建谁守」「要问的是」「点名分工是节目自陈的个人判断」，这些都是站在节目外面跟读者说话，读者要的是内容本身。2026-07-31 从 191 期里清掉了 29 处。
  - **「落点是」这个模板句一律删掉。** 历史上有 25 期用同一个句式收尾，「落点是及时止损」「落点是现金就是权力」「落点是新加坡的前瞻性」。删掉三个字直接说那句判断，句子反而更有力。同类的还有「更狠的一句是」「更要紧的是」这种导读和过渡套话。
  - **空表态要换成理由。** 「本期不接受这个说法」只表明了态度，没给依据。EP191 改的时候删掉这句，用「可」接上后面那条反驳，读者自己就看出厂家的说法站不住。
  - **别为了工整堆对仗。** EP052 一段里连用三个「不是 X，是 Y」，读起来像顺口溜。这个句式本身没问题，纠正一个流行说法的时候很好用，但一段里最多一次。
  - **不用冒号和分号。** 拆成短句，跟正文其它地方的标点规矩一致。
  - 回归检查：EP141–EP145 历史上写过 380–640 字、又被压到 130–145 字两个极端。2026-05-26 全面收紧到 200–250 字带，原 251–350 字的 55 期（EP001/002/003/004/007/008/009/010/012/016/020/027/029/030/036/042/046/047/049/052/053/054/055/059/065/069/070/071/072/075/076/078/081/088/092/098/099/100/102/105/106/107/108/112/113/130/131/132/141/142/144/145/146/147/148）已批量缩写，被砍掉的细节下沉到 `viewpoints` / `topic`。

- `videoLinks`
  可选。用于在节目详情页标题下方显示视频平台图标。
  每个条目推荐包含：
  - `platform`: `bilibili` 或 `youtube`
  - `url`: 视频链接
  - `access`: 可选，普通节目可省略；如果是会员专属内容，填 `member`
  - `status`: 可选，如果平台没有这一期，填 `unavailable`
  - `note`: 可选，用于鼠标移到灰色按钮时显示，例如 `已下架`

- `topic`
  必须按这套结构写：
  - `background`
  - `conflicts`
  - `boundaries`
  - `mechanism`
  - `extensions`
  - `topic.extensions` 写的是“延展话题”，不是固定三条的泛泛读后感。
  - 每期 `topic.extensions` 的主题线数量按当期真实关联节目和话题结构决定：有关联就写，没必要硬凑 3 条，也不要把整期压成 1 条长段落，或者把明显不同的关系强行塞进一条。
  - `2 条`只是主题线数量下限，不是默认模板；也不要把过去的 `2-5 条`理解成链接数量上限。延展阅读里的 EP 链接数量没有上限，只要同一主题线能自然解释清楚，可以串联更多节目。
  - 审查脚本按更严格的底线执行：`relatedEpisodes` 达到 3 个时通常至少写 3 条延展话题；只有关联节目确实只有 1-2 个、且只有两组自然关系时，才保留 2 条。
  - 每条必须用 `关于xxx：` 开头，`xxx` 要短、直观、好理解，优先写成观众一眼能识别的人、事、行业、国家或具体议题，例如 `关于潘石屹：...`、`关于匈牙利：...`、`关于新加坡中立：...`、`关于外卖劳动：...`、`关于学生午餐：...`。
  - `关于xxx` 不是长标题，也不是完整判断句；不要写成 `关于潘石屹为什么提前卖楼`、`关于匈牙利选举与欧盟` 这类过长标题。正文里再解释判断，标题只负责告诉读者“这条在讲什么”。
  - 不要为了凑四个字或六个字牺牲清晰度；也不要写抽象黑话、内部概念或修辞词，例如 `主动中立边界`、`欧洲拆雷教训`、`地产人物止贪`、`潘张婚姻与治理`、`苦难美颜`、`内容流水线`、`内容工业`、`平台遮蔽`、`女性接盘`、`区域拒止`。这些都要改成 `关于新加坡中立`、`关于匈牙利`、`关于潘石屹`、`关于影视审美`、`关于家族接班` 这类普通读者能马上理解的标题。
  - 小标题必须覆盖这一条里串联的整组节目，不能只抓当期素材或其中一个案例。例如一条同时连接 `EP015`、`EP045`、`EP039` 时，标题可以写成 `关于新能源工人`；一条同时连接安全事故、行业背书和工厂反馈时，标题可以写成 `关于电车安全`。
  - 每条延展话题大部分情况下的最低标准，是把本期和至少 2 个外部节目连接起来，并写成同一条主题线。不要把 `relatedEpisodes` 机械拆成“一条只讲一个 EP”的节目推荐；如果某个相关节目只能单独成立，优先考虑并入同主题条目，而不是另起孤立小标题。
  - 冒号后要写清楚节目之间的具体关联：哪些 EP 提供背景，哪些 EP 补规则、利益、制度或后续案例，当期节目在这组内容里接上了哪一环。
  - 延展话题要优先写成“主题线”，不是单点节目推荐。一个小标题下面可以串起多期节目，链接数量没有上限；关键是说明它们在同一问题上的递进：起点是什么、机制如何展开、后果在哪里出现、当期节目补上哪一段。
  - 主题线要简单、顺口、像自然正文，不要写成机械导览。可以让 `EPxxx` 自然嵌在句子里，但不要反复使用 `先看 EPxxx / 再看 EPxxx`、`EPxxx 讲...，EPxxx 再讲...`、`EPxxx 提供...这一层背景，EPxxx 提供...这一层后果；本期补上的，是...` 这类模板句。
  - 同一条里不要连续用 `EPxxx 讲...` 串节目；如果一条里出现两个以上“讲”，优先改成自然句，例如 `EPxxx 里...`、`EPxxx 把...放到...`、`EPxxx 显示...`，或者直接写“这几期放在一起能看到什么变化”。
  - 简单不等于清单化。每条只抓一条最直观的关系，优先写“这几期放在一起让读者看到什么变化”，少写“这一层背景 / 这一层后果 / 补上机制”这类整理者内部语言。
  - 链接密度要服务理解。每期通常应覆盖所有 `relatedEpisodes`，并在确有同题关联时补入更早或更新的节目；但不要为了堆 EP 牺牲判断。新增正文引用某个 `EPxxx` 时，必须同步加入本期 `relatedEpisodes`。
  - 深度标准是“读者看完知道为什么要点过去”。合格写法要指出关联节目之间的因果、制度、利益、叙事或案例关系；低质量写法只是罗列标题、重复摘要、或者说“几期合起来看很清楚”但没有说明清楚了什么。
  - 不要只写"和 EPxxx 连读""适合一起看"。必须说明为什么能一起看，以及这几期合起来让读者看到什么。
  - 当多期节目属于同一话题时，优先按话题分组串联，但标题仍要简短直观。例如 `EP087 / EP097 / EP117` 可以写成 `关于伊朗接班`，`EP122 / EP130 / EP117` 可以写成 `关于东南亚` 或 `关于海峡通行`。
  - **每条 `topic.extensions` 长度 80–130 字，硬上限 150**。EP141–EP145 曾经写到 120–200 字一条，全部要回写到 130 字以内。超长的拆掉，不超长的也要把"嵌套子句、连串顿号、多层判断"压平。
  - **一条只讲一个意思**：一个主题线 + 关联节目 + 当期节目接的那一环。不要把"机制 + 后果 + 反方 + 站点定位"四件事压进同一条里。
  - **句式像自然正文**：避免出现"既……又……"、"不仅……还……、不是……而是……"叠加三层以上，避免一条里出现两次以上分号。读起来要像有人在和你说话，不是 PPT 提纲打包成段落。
  - 自检：单独读完一条 `topic.extensions`，三秒内能复述"这条在说什么"。需要回头看两次才理清的，就是太复杂，砍。
- `topic.mechanism`
  **机制推演的本质是让读者一眼看出"谁连到谁"——它是一条骨架，不是一段论述。**节目的内容、数据、案例、判断都不应该被塞进 mechanism 里；它们的位置在 `viewpoints` 和 `topic.background / conflicts / extensions`。mechanism 越短，关联越清楚；越长，越像复读机。
  - **总长度 150–250 字，硬上限 300**。EP121–EP140 历史区间是 144–308 字、EP141–EP145 曾经写到 379–803 字，全部要压回 250 字以内。EP142 即便已经压到 395 字依然偏长。
  - **5–6 步**，硬上限 7。一步只承担一个"由谁带到谁"的转折。
  - **每步 20–40 字**。超过 40 字基本是塞了细节进去——把细节挪到 `viewpoints`，箭头链只留转折。
  - **禁止内嵌**：不要在一步里塞括号注释、数字对照、产品参数、并列从句、人名罗列。例如"大学扩招 34%->90%，但产业结构没有同步升级、民营经济用工蓄水池反而萎缩"应该整段挪去 `viewpoints`，mechanism 里这一步只剩"扩招速度远超产业升级吸纳能力"。
  - **用词要白话**：能说"政府的钱"就不写"引导基金 LP"，能说"上市套现"就不写"IPO 退出"，能说"算回自己市值"就不写"合并报表"，能说"重讲成另一个故事"就不写"切换估值锚"，能说"过半股份"就不写"51% 控股"，能说"上面最支持的方向"就不写"最政治正确赛道"。专业名词只在第一次出现且无法白话化时保留，整段不能是 VC 路演黑话。
  - **不承担价值判断**：mechanism 负责"为什么会这样运转"，不负责"这套机制好不好、谁该负责"——后者写进 `viewpoints` 末尾或 `topic.extensions`。
  - 自检：单独读完 mechanism，10 秒内能复述这条链上的 5–6 个转折；如果中途要换气、要回头看上一步、要去查某个词意思，就是塞太多。

- `viewpoints`
  必须写成分小标题的观点数组。观点是为读者抓本期主线的锚点，不是把节目逐句切片。
  - 数量 **4–6 条**，硬上限 **6**。2026-05-26 从 6–9 收紧到 4–6：读者抓主线不需要 7+ 个锚点，超出的必须整合不是删除——把承载同一判断方向的两条合并、把 mechanism 切片回流到 mechanism、把案例细节下沉到 `topic` 或单条 `body` 内。EP079/EP128–EP148 共 21 期历史超标，按本规则整合回写。
  - 每条 `body` 长度 **80–150 字**，硬上限 **180**。一条只承担一个判断，承担不下时拆成两条，而不是把第二个判断挤在同一段尾巴。
  - `title` 短句，**8–18 字**，能让读者一眼看出"这条在讲什么判断"。不要写完整论述句、不要在标题里塞数据。
  - 同一判断不要在两条之间互相重复；如果两条标题改一改可以并成一条，就并成一条。
  - 不要把 `topic.mechanism` 的链条切片成 viewpoints；mechanism 是因果链，viewpoints 是独立判断。两者重复时优先压缩 viewpoints。

## 六类内容怎么写

### 节目 `content/episodes/*.json`

负责承接本期的完整结构化整理，是网页详情页的主来源。

如果已经找到视频链接，优先直接写进节目 JSON 的 `videoLinks`，不要拖到最后再补。

```json
"videoLinks": [

  },
  {
    "platform": "youtube",
    "url": "https://www.youtube.com/watch?v=..."
  }

```

如果 B 站是会员专属节目，写成：

## 节目内容怎么做

这一部分是整个知识库最重要的工作面。不要把节目条目理解成“字幕摘要”，而要把它理解成：

- 这一期到底在解释什么
- 它的主判断是什么
- 它把哪些现象连成了一条因果链
- 哪些节点值得被沉淀成长期可复用的概念、模型、人物、主题

### 基本原则

- 先抓“节目真正想说什么”，再写字段
- 不要按字幕顺序机械抄录
- 不要把一堆正确废话拆成 bullets
- 不要写成整理者备注
- 要写成“用户点开就能读懂这一期在讲什么”

### 改写既有条目：禁令与红线

2026-07-30 全库整改定下的，新写条目同样适用。

**禁令**

- **不用破折号 `——`。** 拆成两句，或者换逗号。整改前全库 401 处，是长句最主要的来源。
- **不用「知识库」这个词，主体一律写「本页」。** 「知识库保留为节目语境下的故事案例」这类元叙述是最劝退的写法，改成「本页当一个具体例子收着」。整改前 40 处。
- **不用报幕句**：「值得注意的是」「不难看出」「换句话说」「这一段」「全场的落点」。
- **不要贴标签式收尾**：段落最后一条不写成「这就是[某概念]」「这属于[某概念]那一类」。概念要承担内容，不是承担归类。
- **全站简体中文**，繁体字一个都不许混进来。

**红线：只做文字层面的改写**

改写既有条目时，下面这些改前改后必须完全一致：

- 数字、日期、金额、比例、人名、机构名、节目编号（EP123 / LIVE005）
- 句内链接 `[显示文字](episodes/EP137)`，一个都不能丢
- 各数组的条目数（`conflicts` / `boundaries` / `viewpoints` / `extensions` / `segments` / `points` / `audienceThreads` / `tags`）

**不许新增事实、不许改数字、不许加原文没有的细节。** 拿不准的句子保持原样，不要瞎猜。

改完拿脚本逐文件跟 `git HEAD` 比一遍数字集合和链接集合，别靠肉眼。2026-07-30 整改时靠这个查出 5 处事实丢失，包括 EP148 被压掉的「路特斯 IT 主管」和「六人被捕三人定罪」、EP146 丢掉的 2027 女足世界杯。

**这些规则对 `boundaries` 同样生效。** 整改时把 `boundaries` 漏在改写范围外，结果那里独自留着「主播即兴口播」和一堆超长的数字列举句。

### 人称：无主语陈述（全站标配）

**正文里不出现指主播的人称。** 不用「主持人」「他说」「他的判断是」，也不用「我」。用户 2026-07-30 定的口径，2026-07-31 扩到节目与 `boundaries`：句子仍然以主播为逻辑主语，但字面上把这个主语隐去。

做法是删掉称呼和转述外壳，直接陈述：

- 改前：`是主持人朋友家孩子的真实经历`
- 改后：`是朋友家孩子的亲身经历`
- 改前：`主持人本人在科委工作一个月即辞职的回忆`
- 改后：`在科委干一个月就辞职那段回忆`
- 改前：`是主持人对学者社会角色的价值倡导`
- 改后：`是对学者角色的主张`

**`topic.boundaries` 同样适用。** 这一条覆盖 `sop/08` 里「boundaries 整个不动」的旧例外。边界声明照样写成无主语，主体用「本页」承担（`本页按观点收`、`本页只当方向和量级看`）。

**唯一例外：节目里人物说的话原样保留**，包括引号内的第一人称和第三人称。郑强、岳不群这些人物的「他」不是主播的「他」，不要一起删掉。

删掉主语之后每句都要重读。批量替换最容易把动词一起吞掉，出现过「他讲了X」变成「了X」这类断句，全部要扫出来补回。

### 句子长度：一句不超过 40 字

2026-07-30 全库整改。整改前 33.9% 的句子超过 40 字，最长的一句 100 字以上，读者反馈是「看着累」。

**一句 40 字以内。** 超了就重组成几句短的，注意是**重组成连贯的短句流，不是砍成碎片**。

- 坏（碎片）：`1911 年 3 月 25 日，星期六。纽约曼哈顿三角内衣厂八楼。移民女工正在赶工。`
- 好（连贯）：`1911 年 3 月 25 日是个星期六，纽约曼哈顿三角内衣厂的八楼车间里挤满了移民女工。通往楼梯的逃生门被锁着，钥匙在工头手里。`

**量长度按读者看到的字算。** 句内链接 `[学术官僚化与知识退化](themes/academic-bureaucracy-and-knowledge-decline)` 源码 61 字符、显示只有 10 字。统计时先把 `[显示文字](路径)` 还原成显示文字、去掉 `**`，再数长度。用源码字符数会得出一个虚高一倍的数字，2026-07-30 这个坑踩过一次。

**`summary` 和 `topic.background` 控制在 200 字、最多 2 段，但字数让位于事实完整性。** 200 是目标不是硬上限。判决年数、涉案人数、日期、金额这类信息密的期数，压到 200 字必然要删事实，那就别压。EP148 压到 200 字时丢了路特斯 IT 主管的身份、4500 人围观群组、六人被捕三人定罪，只剩个空壳，后来回退到 467 字两段。

**摘要不要分点铺开。** 不写「一是……二是……三是……」，也不要每两句一个空行。多数情况一整段就够。

### `topic.mechanism` 的小主题

机制链每一步写成 `小主题：一句话`，步与步之间用 ` -> ` 连接（半角，不要用全角 `→`，前端识别不了）。前端把每一步渲染成独立的块，小主题金色加粗排在左侧，正文跟在竖线后面，块之间一个向下箭头。

**小主题写内容领域，不写动作，也不复述正文。** 用户 2026-07-30 定稿。读者扫一遍小主题，看到的应该是这一期跨了哪几个领域。

- 好：`舆论传播 -> 国家信用 -> 劳动保障 -> 住房制度 -> 土地循环 -> 制度信用`（EP140）
- 好：`产业观察 -> 社会心理 -> 资本与公司 -> 国家路径 -> 文化与规则`（LIVE028，直播用话题分类，同一类词）
- 坏：`流量把两段拼一起`（复述正文，读标题和读正文重复一遍）
- 坏：`断章拼接` `偷换问题` `账算到个人`（这是动作，不是领域）
- 坏：`远程锁车`（事件名）

判断标准很简单：**这个词能不能当一个栏目名。** 「国家信用」「住房制度」能，「断章拼接」「账算到个人」不能。

常用领域词（不是封闭清单，按内容取）：舆论传播、社会心理、社会分层、国家信用、国家路径、制度设计、政企关系、资本与公司、产业观察、金融市场、劳动保障、住房制度、教育与代际、文化与规则、科技与 AI、地缘博弈、个人选择、长期主义。

小主题 2 到 10 字，不能带逗号句号。同一期里领域词可以重复，但相邻两步不要重复。

### 机制链的正文与步数

**一期 5 到 6 步。** 步数多了主题就散，读者找不到重点。EP140 一度写成 7 步七个主题，看下来不知道这期到底在讲什么，砍掉「护照价值」和「土地循环」两步后（它们是前一步的展开，不是新环节），只剩两个谣言和一个共同落点，重点自己就出来了。直播不受这条限制，见 `sop/08`。

**每步一句话，25 到 40 字，一行装得下，结尾带句号。** 超过一行会在版面上换行到标题下方，整块看着乱。

**正文必须落在自己的小主题上。** 只讲事情经过、不点到主题，主题就是悬空的。

- 悬空：`国家信用｜放回原场景，他哽咽是在读一封公民来信。写信人从中东撤离，搭军机回国，在飞机上唱起了国歌`（讲了经过，没讲这跟国家信用什么关系）
- 落地：`国家信用｜他哽咽是在读一封公民来信，那人被困中东，国家派军机接了回来`（国家为公民做的事，就是信用本身）

**每一步要接得住上一步，整条链读下来是一个故事。** 不是把六件事并排放着。

EP140 这条线：自媒体剪出谣言 → 他哽咽的真实原因 → 同场还讲了什么 → 另一个谣言 → 两件事其实是同一个逻辑。前后有承接词（`同场还讲了`、`另一个说法是`），读者跟得住。

**不要用编辑口吻。** 「放回原场景」「节目把国家信用延伸到组屋」「后半段转向」这类是在讲节目做了什么，不是讲事情本身。直接说事。

**写之前先把整期读完。** 只盯着旧机制链改字，会写出`把哽咽和新加坡危机剪成同一段`这种不通的句子（危机不是能剪辑的素材）。先读 `summary`、`topic.background`、`viewpoints`，弄清楚这期到底讲了什么，再动手写链条。

**每写完一期，回头问三件事**：这句话本身通不通；这个主题配不配得上这段内容；这些主题连起来是不是一个能看懂的结构。

**每步本来就是短语的不要加。** 例如 EP001 的 `高咨询费投入 -> 品牌符号被强化 -> 组织围绕老板偏好收缩反馈`，短语本身就是脉络，再套一层标题只会重复。全库有 26 期属于这类，保持原样。判断线是每步平均 15 字以内。

直播侧的机制链写法不同，小主题直接用该场的话题分类，见 `sop/08`。

### 节目页的黄金标准

当前节目条目的参考标准是：

- `EP001`

它的特点不是字多，而是结构完整：

- 有明确主判断
- `topic` 不是空架子
- `viewpoints` 每条都有独立判断价值
- `concepts / models / people / themes / relatedEpisodes` 都不是装饰
- 节目本身能反向推动节点层变厚

整理新节目时，默认以 `EP001` 的完成度为目标，而不是以“能显示出来”为目标。

## 如何从 transcript 提炼节目主线

### 第一步：先找主判断

先回答一句话：

- 这期最想说的核心判断是什么？

如果这句答不出来，就不要急着填 JSON。

正确做法：

- 先把节目里的判断压缩成一句话
- 这句话必须带方向感，而不是中性复述

例如：

- 不要写：`节目讨论了银行直供房、法拍房和房价问题`
- 要写：`节目把银行直供房视为法拍通道装不下风险后，银行为回收流动性开辟的新处置路径，而不是楼市见底信号`

### 第二步：再找它的论证链

问自己：

1. 它拿什么现象开头
2. 它把这些现象解释成什么机制
3. 它最后落到什么判断或建议

通常可以整理成：

- 起点现象
- 核心矛盾
- 解释机制
- 最终落点

### 第三步：只保留节目真正强调的部分

不是 transcript 里出现过的每句话都值得进结构化条目。

优先保留：

- 反复出现的判断
- 串联多个细节的解释框架
- 节目最后明确落下来的结论
- 能沉淀为概念/模型/主题的材料

不要保留：

- 顺口评价
- 噱头式句子
- 无法独立成立的感叹
- 只在节目里轻轻带过、没有展开的点

## 各字段具体怎么写

### `summary`

`summary` 不是“本期聊了什么”，而是“本期的主判断是什么”。

长度硬标准（**200–250 字**，2026-05-26 收紧）见本文件开头「节目条目字段规范 → `summary`」一节，那里是唯一权威口径。本节不再单独规定句数，只讲怎么写好这 200–250 字：

- 第一层说切入点
- 第二层说核心判断
- 如有必要，第三层说为什么重要
- 几句话不是硬指标，关键是落在 200–250 字带内、单独读 8 秒能读懂本期主判断

错误写法：

- `本期讨论了房票在各地流通的现象`
- `本期从豪宅市场切入，进行了深入分析`

正确方向：

- `本期围绕房票流通、折价出售和中介炒作展开，判断它不是楼市重新启动的信号，而是地方政府在现金吃紧时用票据代替部分现金、继续拖延出清的一种工具。`

### `topic.background`

写“节目是从什么现象切进来的，为什么这个现象值得讲”。

不要写百科背景。

要写：

- 这一期的现实入口
- 节目为什么拿它当样本
- 它和更大结构之间的关系

### `topic.conflicts`

写节目内部真正的矛盾，不是泛泛而谈的“支持与反对”。

要尽量写成两股力量或两种解释的对撞。

例如：

- `豪宅市场的坚挺，究竟是独立稀缺市场，还是整体楼市回暖信号`
- `房票流通是在激活真实需求，还是在延缓价格出清`

### `topic.boundaries`

写这一期没有做什么、不要误读成什么。

这个字段很重要，因为它能防止节目页显得全知全能。

常见边界包括：

- 不是法律审查
- 不是全面事实核查
- 不是对所有城市/行业的普遍结论
- 不是给个体投资建议

### `topic.mechanism`

这是节目页最值钱的字段。

最好写成因果链，而不是一个抽象句子。

推荐结构：

`A -> B -> C -> D`

例如：

- `断供增加 -> 法拍通道承载不足 -> 银行开辟直供房路径 -> 折价房源增加继续压低预期`

### `topic.extensions`

这里写的是“从节目内部还能自然延伸出的下一层问题”，不是整理者自我提醒。

正确方向：

- 继续追问
- 提出可讨论的结构问题
- 指向更大的长期议题

错误写法：

- `这一期可以作为后续整理地产主题的重要案例`
- `后续整理时可以沿着这个维度继续展开`

正确写法：

- `如果房票越来越普遍，未来楼市会不会出现票面价格稳定、真实成交价格不断场外折价的双轨市场`

### `viewpoints`

`viewpoints` 是最容易写差的部分。

最低要求：

- 每一条都必须是一个独立判断
- 标题和正文之间不能只是重复改写
- 不能把 summary 拆碎了重复说 6 次

好的 `viewpoints` 应该满足：

1. 这一条单独拿出来也成立
2. 它说的是节目里的一个具体判断，不是空话
3. 它和其他条之间不要重叠太多

推荐写法：

- 标题写判断
- 正文写证据、展开和后果

错误例子：

- 标题：`房价下跌可能不是一次到位，而是分阶段释放`
- 正文：`节目认为房价下跌可能不是一次到位，而是分阶段释放`

这类写法基本等于没写。

正确方向：

- 标题：`银行直供房不是抄底信号，而更像第一轮出清已经开始的标记`
- 正文：解释为什么节目会这么判断、后面还会看哪些信号、这对判断市场意味着什么

### `extensions`

根节点的 `extensions` 要写成“用户读完这期后自然会继续追问什么”。

- 每条 **30–80 字，硬上限 100**（现存节目中位 40 字）。它比 `topic.extensions`（80–130 字）短得多——是一句开放追问，不是一段论述；写长了就该压。

不要写：

- `这一期适合与 XX 联读`
- `这一期可作为后续整理的入口`
- `整理时可继续沿着 XX 展开`

要写：

- 真正的问题
- 下一层判断
- 节目没有完全讲透、但已经被打开的方向
