## 目标

新一期节目从 B 站/YouTube 发布，到网站上线，尽量少人工。把整条流水线拆成「机械活」和「判断活」两类：机械活全部脚本化、可无人跑；判断活（内容创作）留给对话里的整理者（LLM）。

## 流水线全景（新一期从发布到上线）

| 步 | 动作 | 谁做 | 无人自动 |
| --- | --- | --- | --- |
| 1 | 扫 B 站 UP 投稿列表，发现新 EP 号 | `scan-new-episodes.py` | ✅ |
| 2 | 判断会员/非会员、取发布时间 | 同上 | ✅ |
| 3 | 下载 AI 字幕存 `raw/`（充电后会员也能下） | 同上（调 `fetch-ai-subtitle.py`） | ✅ |
| 4 | `npm run srt` 生成草稿 JSON | 同上 | ✅ |
| 5 | 写 `summary/topic/viewpoints` | **整理者（LLM）** | ❌ |
| 6 | 抽概念/模型、判断影射写边界声明 | **整理者（LLM）** | ❌ |
| 7 | 建关键词词条、双向回填、写网页日志 | **整理者（LLM）** | ❌ |
| 8 | 字数自检、繁体扫描 | 脚本 | ✅ |
| 9 | `npm run build` + `test:ui` | 脚本 | ✅ |
| 10 | `git commit` + `push yinfluence-origin main` | 脚本 | ✅ |
| 11 | 线上验证（`site.json` 期数变化） | 脚本 | ✅ |

**唯一必须有 LLM 的是第 5–7 步**（判断性内容创作）。这是整条流水线的核心约束：cron 脚本再全，也写不出 summary、判断不了影射边界。

## 两种运行模式

### 模式 B（推荐）：定时备料 + 一句话触发

- **每天 20:10（中国时间 = UTC 12:10）**，cron 跑 `scan-new-episodes.py`：发现新期 → 下字幕 → 生成草稿 → 写 `workbench/pending-episodes.json` → 发系统通知/推送「EPxxx 已就绪，字幕已下载，来喊我整理」。
- 用户看到通知，在对话里说一句「整理新一期 / 网页更新了」。
- 整理者（LLM）：读 `workbench/pending-episodes.json` + transcript → 完成第 5–7 步 → build → push → 线上验证 → 回报「EPxxx 已上线」。
- 优点：机械活全自动、用户零操作就备好料；内容由 LLM 在线整理，质量可控（字幕错字校对、影射边界判断都在）。缺点：需要用户一句话。

### 模式 A（最大化自动化）：定时唤起 LLM 全自动

- 用 Claude Code 的 `schedule`（定时 cloud agent）每天 20:10 唤起整理者。
- 整理者自己跑 `scan-new-episodes.py`，有新期就完成第 5–11 步全流程并上线，发通知；无新期静默退出。
- 优点：真正无人值守。缺点：全自动上线，若 LLM 对影射边界/字幕错字判断失误直接上线无人审；依赖 `schedule` 可用 + cookie 不过期。

### 模式 D（当前在用）：launchd 定时唤起本机 claude 全自动

- `~/Library/LaunchAgents/com.yingxiangli.daily-auto.plist` 定时跑 `scripts/auto-daily.sh`：扫描 → 有新期则以 `scripts/daily-agent-prompt.md` 唤起 headless claude 完成整理、build、push、三步验证；无新期静默退出。日志在 `logs/auto-daily-YYYY-MM-DD.log`。
- 发布规律（2026-07-23 核实最近 30 期）：北京 19 点档 10 期、20 点档 18 期、23 点档 1 期，EP188 实际 20:50。用户确认按 20 点为主对齐。
- 调度（2026-07-23 定稿）：launchd 每天英国本地 12:10 与 13:10 各触发一次（两个点保证 BST/GMT 时差下总有一个≈北京 20:10），外加开机 RunAtLoad 补捞。脚本自身在北京 20:05–22:30 窗口内每 10 分钟重扫，扫到新期整理完即停；窗口外触发只扫一次。
- 三条止损规则：全程 mkdir 锁——已有实例在扫或 claude 在整理时后续触发直接退出；一天只有一期——库里最新一期 publishedAt 已是当天（UTC）就当天收工不再扫；无新期时最晚扫到北京 22:30。2026-07-23 前是每 3 小时盲轮询，EP188 落在两轮间隙 1 小时无动作，故改此方案。

### 模式 C（最简）：纯一句话触发，无定时

- 不设 cron。用户想更新时说「检查网页更新」，整理者跑扫描 → 有新期就整理上线并回报，无则回「暂无新一期」。

## 触发词（整理者识别）

用户说以下任一，整理者执行「扫描 → 若有新期则备料 → 整理 → 上线 → 回报」：

- 「网页更新了 / 网页是否有更新 / 检查更新 / 有没有新一期 / 整理新一期 / 自动跑一下」

## 关键约束（决定自动化能不能长期跑）

1. **颖响力充电必须保持有效**。充电后会员视频 `player/wbi/v2` 才返回字幕轨（见 `sop/02`）；过期则新会员期字幕又拿不到、脚本第 3 步失败。
2. **B 站 cookie 会过期**。脚本默认从 Chrome 现导（需 Chrome 保持 B 站登录）；无人 cron 环境要保证 Chrome 登录态或维护一份长期 cookie。cookie 失效时脚本以退出码 1 + 明确报错停下，不会静默产出脏数据。
3. **影射类节目仍需人工判断边界**。凡标题/内容用《笑傲江湖》等化名影射（如 EP153/170/187），整理者必须写「化名影射、非事实指控」的边界声明，这一步不可全自动省略。
4. **AI 字幕同音错字**必须对照修正（「颖响力」→「影响力」、「大棋」→「大旗」、「小厮」↔「小斯/小司」等）。
